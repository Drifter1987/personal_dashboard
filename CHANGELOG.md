Release notes for the Home Dashboard, newest first. Generated from the `CHANGELOG` array in

The running page is **v2.23.0**; the newest entry below is **v2.23.0**.

## 2.23.0 — 2026-10-17

Searching now lands on the word, not just the card. Picking a suggestion used to outline the whole card and leave you to find the keyword inside it; the matched word is now marked in the accent colour for three seconds - long enough to catch the eye, short enough to leave the page as it was - and a shut Settings group holding it opens first, so searching "language" opens Appearance and marks Language on screen. A phrase that is not in the card falls back to its first long word that is, and a card with no visible match still outlines as before. Three smaller reads are fixed with it: the GitHub card's star and count moved out of the headline into a right-hand column of fixed width, so every row's star starts on the same edge instead of drifting with the digit count; a news row that states no free allowance draws no chip at all, where it used to draw an empty dashed oval holding a dash; and the QR card's share buttons are a grid of labelled brand tiles - WhatsApp, Instagram, Snapchat, Email, Copy link - drawn as inline marks so they still exist offline, instead of five loose text buttons wrapping over three rows.

## 2.22.2 — 2026-10-17

A card is now as tall as what it holds. The page's two columns are a grid, and a grid stretches every item to the tallest in its row - so the clock, a one-line quote or the metals list drew a few hundred pixels of empty card below its last line, next to a full-height neighbour. Cards size to their own content now, and the layout contract measures it: it walks all six sections and fails if any card ends more than a line of spacing below its last child, so a stretched card cannot come back unnoticed. One consequence is handled rather than hidden: when hiding a card leaves the page shorter than your offset, you land at the page's end instead of being carried back up toward the card under the header. The case that hides a card above the fold now hides one that is genuinely above it - the old one picked whatever reached past the header, which was a different card once the layout stopped stretching.

## 2.22.1 — 2026-10-17

Opening the dashboard is opening it, not resuming the document. With the section no longer remembered, the browser still restored its own scroll offset, so Home could open halfway down the page - and it did so only on a slower machine, which is how the layout contract caught it in CI after passing locally. The page now owns its scroll restoration and starts at the top, while a ?p= link still opens its section at that section's top. The contract also stopped reading the phone's pager mid-scroll: it waits for the settled position, so a slow runner measures where the pager came to rest instead of reporting an animation as a bug.

## 2.22.0 — 2026-10-17

Reopening the dashboard lands on Home, and only Home. The address used to record the section you were reading (?p=), which meant a closed app came back to Markets or Settings days later; a section is now a place you go, not a memory the app keeps for you, so the address is never rewritten as you move around. A link that names a section still opens it - the manifest's shortcuts and a shared link carry ?p= and keep working - because that is someone handing you a page, not the app remembering. The layout contract grew to match: it now proves a reload opens Home whatever section you left, that a card body holds the height it had while its next batch of data is loading (a bounded wait releases the frame if the new content really is shorter, so a card cannot leave a hole), and that pressing the theme button, a card's refresh or a calendar arrow leaves the section and the offset exactly where they were. That contract is a CI job of its own now, and publishing waits for it. And the page's five parallel card tables - section and search words, icons, names, painters and refresh actions - are one registry, so adding a card is a single entry instead of five edits that could disagree.

## 2.21.1 — 2026-10-17

The scroll behaviour is a test now, not a promise. A small Chromium contract drives the real page and measures what a person notices: turning a card off or moving one keeps the page exactly where it was, the card under a hidden one does not shift, a page that became shorter than your offset clamps instead of jumping to the top, a section change still opens at the top, the phone keeps its section and its side offset, and Today still rests on the month you are in. Writing it shrank the fix: only the document and the phone's pager can ever scroll, so a rebuild no longer tracks containers that cannot move.

## 2.21.0 — 2026-10-17

The dashboard stopped jumping. Hiding a card, reordering one, switching language or turning a chip off rebuilt every card from scratch, and the page you were reading snapped back to the top each time - the rebuilt list is briefly shorter than the scroll you had, and the browser clamps it. A rebuild now remembers the card under the header and puts it back on the same line, keeps the pager's horizontal position on a phone, and returns to the top only when you actually change section.

## 2.19.1 — 2026-10-17

The blank page is fixed, and it was ours. The offline worker precached the shell from /index.html, which the host answers with a 308 to /, so the copy it stored was flagged as a redirect - and a browser refuses a redirected response for a navigation, which is why the address opened to an error page while the site itself was answering 200. The worker now copies the shell from / where there is no redirect, refuses to serve a redirected copy even if an older release left one cached, falls back to the network when the cache itself cannot be opened, and takes over at once when it inherits a cache no page can load, so a browser stuck on the old worker repairs itself instead of waiting for someone to clear site data by hand.

The month and year now sit in a fixed frame as wide as the longest month name in the language, with an arrow on each side, so the arrows stay where your finger expects them instead of sliding about as May becomes September.

## 2.18.0 — 2026-10-17

## 2.17.1 — 2026-10-17

A refused test reminder says which refusal it was now. The last release taught it to ask the browser before judging; this one separates the answers it was lumping together. A permission the browser reports as not granted is named as blocked, with the host to allow it on, and a browser that never shows a permission prompt at all says exactly that instead of claiming the prompt was dismissed. When the device still refuses to draw the notification, the reason the browser gave stays under the switch - no show event, an error event, or the worker's own refusal - rather than one sentence that read the same however it failed.

## 2.17.0 — 2026-10-17

The free image and video tools move to News, where the rest of the reading lives, and the last tab is just Settings. Settings itself is a stack of six cards now - appearance, review window, cards, reminders, data sources, about - and each opens where it stands instead of scrolling one long column; a shut card still says what is inside it, from the theme in force to whether reminders are armed, and the card you open is the one that is open next time. Cards can carry files as well: PDF, Excel, images, text and scripts, added from the card dialog and counted on the card itself. The bytes go to this browser's own file store rather than the settings record, so the JSON export stays small and nothing is uploaded anywhere; deleting the card deletes its files with it. And the saving is no longer silent: tasks and settings are written on every change, written once more when the page is hidden, and if the browser refuses to save - a full quota, a private window - the page says so instead of forgetting quietly.

## 2.16.0 — 2026-10-17

The test reminder tells the truth now. Sending one used to answer that notifications were blocked before the browser had ever been asked, because the button read the permission instead of requesting it; it asks on the tap now, so a first run gets the prompt rather than a refusal, and an answer of no names the app and the host and says where to allow them. The reminder section also follows a permission that changes while the page is open, so it stops saying blocked the moment it is not. The test proves the device end first - a notification is drawn here before any push is sent - so "this phone can show one" and "a closed app receives one" fail and pass separately instead of arriving as one vague failure. Release notes are held to the same rule as every other string: a note missing a language the app offers, or carrying one it does not, now fails the build instead of reading empty for that reader.

## 2.12.0 — 2026-10-17

## 2.10.0 — 2026-10-17

Reminders now reach the phone when the app is closed. Switch them on in Settings and pick an hour: the page asks the browser for permission, registers a service worker and a push subscription, and hands the Worker the schedule it needs to keep — the local hour, the timezone and the titles of open cards that carry a due date. A cron tick every fifteen minutes fires on the first tick at or after that hour, in your own timezone, and sends one notification listing what is due today, in English or Arabic. The service worker caches nothing, so this changes nothing about how updates arrive.

## 2.4.0 — 2026-10-14

No new card this time — this release is the page and the Worker doing less work for the same result. The clock rebuilt its whole card every second (five elements created and thrown away, plus a fresh date formatter each tick, ~75us of it measured in the browser); it now builds once and writes only the digits that changed, through one cached formatter per language. Every figure in the coin, currency and metals tables went through Number.toLocaleString, which builds a formatter on every call: memoised, the same output costs ~1.1us against ~36us per row, and eastern digits are mapped by code point — 3.4x faster than the string replace, and no allocation. On the API side the Worker hands the edge-cache write to ctx.waitUntil instead of holding the response for it, and serves a cached payload as a stream instead of decoding the JSON to a string and re-encoding it, so neither the write nor a re-encode sits between the request and its bytes.
